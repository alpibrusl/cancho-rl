reinforcement learning · written in cancho

Train on a reward you have already tried to cheat.

cancho-rl grades a program the way a test suite would: the compiler builds it, runs it against a hidden oracle, and returns a number. The reward and the task set are measured first. Only then does a model train on them.

A broken program is a reward

Anything the candidate does wrong, a syntax error, a trap, a hang, is a status and a zero. It is never a crash of the trainer.

A split nobody can tune on

Which tasks are held out is a function of the task's name, so adding a task never moves another across. The prompt never carries a hidden case.

stats ci bootover tasks, not samples

Intervals from the sibling tools

Rates come with a bootstrap interval from cancho-stats; the unit is the task, because a task's eight samples are not independent draws.

How it works

Six seams: policy, environment, rollout, estimator, objective, evaluator. The first instance fills them for a language model that writes cancho; a control instance comes second, and a shared layer is extracted only when the second one starts.

1. A task

A directory: task.spec (the signature, a description, three public examples, the hidden cases), an oracle.cho and a reference.cho. 104 so far, each tagged branch or loop by a mechanical rule the gate re-checks.

2. A grader

rl grade wraps the candidate and the oracle into one test file, runs cancho test under a wall deadline that kills the whole process group, and prints one JSON line.

3. A gate

Every reference must solve its task; every probe must score what it should; for the first 34 tasks an independent Python port of the oracles must agree. A check counts only after it has been watched failing once.

Use cases

One is built and being measured. The others are designed, not built; each says what it is waiting for.

A small model that writes cancho

Built, R1 under way. GRPO with LoRA on Qwen2.5-1.5B-Instruct. The reward is the compiler's own verdict, so it improves exactly what the language tooling already measures. A torch/peft reference run comes first; a cancho-gpu run must equal it before it is trusted.

Auditing any reward before training

Built. The grader, the probes and the gate are reusable on their own: point rl grade at any task directory and see whether an empty program, a constant, an early exit or a mutant earns anything. If it does, the reward is wrong, and you learn that before a GPU hour is spent.

A control task on a simulator

Designed. The cancho-afm digital twin (a board, a plant, a PID loop, about one second a run) is the second instance, with the controller's gains as the policy. The grader there is a measurement of the twin, not of the instrument, and the design says so. Waiting on cancho-afm#31.

Learning inside a safety envelope

Designed. cancho-robot's kinematics and safety rules fix the bounds; what learns cannot change them. There is no simulator yet, so nothing here is claimed. Waiting on cancho-robot#41.

Measured, not promised

The untrained Qwen2.5-1.5B-Instruct, eight samples per task, 95% bootstrap intervals over tasks, on the first 80 tasks. Loop tasks are the hard side.

104tasks, each solved by its own reference in the gate (34 also cross-checked against an independent Python port)
23.1%base solve rate over 80 tasks, interval 17.3 to 29.7%
41% / 13%branch tasks against loop tasks on the train side, 17 and 40 tasks
36 MBpeak memory of a program that recurses forever, graded in 0.7 s

Known limits: the CPU limit (ulimit -t) does not stop a runaway on macOS, so the wall deadline is what works; 38 of the 104 tasks are at zero for the base model and carry no training signal yet; the intervals describe these hand-written tasks only. The full tables are in docs/design.md, sections 17 to 25.

Try it

Build it from source. You need git, Rust and the cancho compiler; sampling a model also needs mlx_lm on Apple silicon.

git clone https://github.com/alpibrusl/cancho                    # the compiler
git clone https://github.com/alpibrusl/cancho-rl && cd cancho-rl
(cd ../cancho && cargo build -p cancho)
export CANCHO=$PWD/../cancho/target/debug/cancho
scripts/gate.sh                                              # builds build/rl, grades every reference and probe
scripts/tools.sh                                             # optional: cancho-stats and cancho-tools, pinned
scripts/sample.sh Qwen/Qwen2.5-1.5B-Instruct 8 work/s1       # sample and grade; one GPU job at a time

The command line is rl grade | split | prompt | report | tasks. Every refusal has a rule tag: rl.usage, rl.task, rl.input.
